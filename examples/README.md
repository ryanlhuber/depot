# Examples

This directory owns non-canonical demonstrations, reference usage, composition examples, and sample implementations.

Examples must not contain hidden requirements or become the source of canonical guidance. Reusable expertise belongs in [`skills/`](../skills/), role definitions in [`agents/`](../agents/), orchestration in [`workflows/`](../workflows/), concrete adapters in [`integrations/`](../integrations/), and repository standards in [`docs/`](../docs/).

Examples should link to the canonical artifacts and documentation they demonstrate and clearly identify technology-specific assumptions.

## Current examples

- [Requirements from a vague brief](requirements-from-vague-brief.md): a loose booking-page brief becomes numbered requirements, with unknowns kept as open questions.
- [Heuristic review of a settings flow](heuristic-review-of-settings-flow.md): findings with severity and confidence rated separately, and items marked for user validation.
- [Synthesis of interview notes](synthesis-of-interview-notes.md): themes and insights that trace to sources, with contradictions and gaps reported.
- [API for a disclosure component](api-for-a-disclosure-component.md): three fictional call sites become one component interface, with state ownership, an accessibility contract, and unresolved questions kept visible.
